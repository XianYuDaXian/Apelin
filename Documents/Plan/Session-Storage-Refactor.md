# 会话可靠性与大历史按需读取计划

修订日期：2026-10-29。代码基线：Apelin 0.2.6，提交 `308d31574e15eee21b154a3f6fca14a8e2671a39`。

Apelin 的目标场景是移动设备上的低并发运行，同时允许单个会话积累百万到千万级历史事件。并发请求数与归档容量分别设计：修复少量请求重叠造成的状态错误，让旧历史留在磁盘，正常打开只读取当前状态、必要的模型上下文和有限的最近内容。

三个版本只是迭代窗口，不是三次大型重构承诺。先修已确认故障，再完成大历史按需读取，最后根据实测处理剩余问题；不为了填满版本增加功能或切换数据格式。本计划尚未实施，不修改当前版本配置。

## 固定边界

- **不引入 SQLite**，不引入其他数据库、ORM 或通用存储框架。不以 Codex 的架构或规模作为选型依据。
- **不修改、不升级、不 fork kwwk，不修改依赖检出内容，不等待上游补丁。** 固定 revision 为 `fb74cf5d855a6dbc60da38187e10d012e30a240a`，以 [Package.resolved](../../Apelin.xcodeproj/project.xcworkspace/xcshareddata/swiftpm/Package.resolved) 核对。
- 优先保留既有日志、模型上下文和协议身份，使用局部初始化保护、小型摘要及可重建索引。新增机制须说明它解决的已复现问题、较小方案为何不足，以及维护成本。
- root 宿主继续掌握权限与审批。摘要和缓存不能成为授权依据；恢复不能重新授予审批。
- 模型上下文与展示历史分开处理，保留消息顺序、工具调用 ID、签名、不透明供应商字段及提示词缓存语义。归档保留可查询历史，不改变模型上下文。
- 不自动重执行结果不确定的副作用，不承诺进程死亡后精确续跑工具。已接收输入不得因去重记录而静默丢弃。
- 本轮只规划文档。产品代码、依赖、数据迁移和设备安装另行实施。

## 证据与问题范围

现场日志样本已有 684,540 条事件、63,317,525 字节，思考增量约占 86%；模型上下文约 233 KB，没有图片块。百万到千万级历史是容量要求，不是服务器级并发假设。现场约 104–105 秒才开始转发历史是端到端观测，不能全算作 JSON 解码时间；没有充分证据将事故定性为互斥锁死锁。

| 问题 | 核实结果 | 处理边界 |
| --- | --- | --- |
| 打开重入 | App 已合并本进程内的打开，worker supervisor 已合并进程启动；宿主会话登记与 worker 初始化仍有重入窗口。 | 补缺失的初始化保护，不重做并发框架。 |
| 首次打开身份 | 新聊天请求的 sessionID 可为空，收到成功回复后才保存；超时重试可使宿主再次生成 ID。 | 首次请求前确定并保留会话身份，重试及重连复用。 |
| 终态吞掉 | 重放过滤可吞终态并推进游标，任务已结束而界面仍工作。 | 权威任务终态直接收敛；旧轮次的 finished 不能误结束新轮次。 |
| 历史读取 | 打开多次完整扫描，worker 从序号零转发全部历史，无界缓冲放大内存。 | 取消正常打开的全量读取和重放；单次流式扫描仅是过渡或重建手段。 |
| 消息中断 | 输入先记录，模型上下文主要到轮末保存；中间退出后，旧 ID 可能被去重但没有进入恢复的上下文。 | 先复现并明确中断、待处理与重试结果，不以完整检查点体系作为前提。 |
| App 与附件 | 聊天整份读写，草稿内嵌附件；模型图片也可内嵌 Base64。 | App 不能抵消后端按需读取的收益；附件优化按真实读写与内存成本单独决定。 |

## 按需读取的最小组成

| 数据 | 正常打开时的处理 |
| --- | --- |
| 当前运行状态 | 读取小型恢复摘要，包含必要的日志位置、标题、轮次状态及提交／待处理信息；不内嵌完整历史。 |
| 模型上下文 | 沿用现有 transcript.json，只加载运行模型所需内容，不从展示事件重新构造。 |
| 最近内容 | 读取小窗口或按稀疏字节偏移定位的内容；按消息边界解释，按字节预算读取，单条超大消息也不能突破预算。 |
| 百万到千万旧事件 | 保留在磁盘归档，用户或工具明确请求某段历史时才读取对应范围。 |
| 摘要之后的事件 | 补读尾部并更新摘要；摘要更新不能长期落后，让正常打开重新扫描大量归档。 |

小型恢复摘要和定位索引是可重建的派生数据。先完整写入对应日志，再原子替换摘要；摘要不得超前宣称不存在的事实。必要消息去重信息也须按提交边界或磁盘查询组织，不能将每条历史事件搬进一个不断膨胀的“小摘要”。

首次处理旧格式、摘要损坏或日志身份不匹配时，允许显式进行一次流式重建，有进度且可中断。不能将一次性重建包装成每次冷启动的常规步骤。保留已有任务日志的残缺尾行、不可读事件及终态不倒退规则；异常不能默认为空会话。

历史与实时订阅以明确的源序号边界衔接。优先沿用已有 `(sessionID, sourceSeq)`；合并记录需要时携带源序号范围，不另造每事件 UUID 或持久化运行代次。旧 worker 的事件与退出优先通过实际对象身份和任务归属隔离。

现有大文件可直接作为旧归档，通过一次扫描建立必要定位信息，无须重写千万条事件。新日志可以继续追加，也可以为便于限制尾部而简单按大小封段；只有需要时才增加段清单，不建设通用事件存储引擎。归档不能只是换目录，正常打开和订阅必须实际停止全读旧文件。

## 三个迭代窗口

### 第一窗口 修复已确认故障

**改动范围**

- 固定首次打开的会话身份，补齐宿主和 worker 初始化保护；请求各自保留权限校验和响应身份，失败后能重试。
- 处理旧实例迟到事件、终态收敛，以及已消费终态的旧聊天。复用现有对象和任务关系，不引入通用调度器。
- 复现输入已接收但上下文未保存的退出窗口，明确中断与重试结果；需要时增加最小提交边界，不自动重跑工具。
- 合并重复日志扫描；将相邻文字／思考增量在原始日志写入前有界合并，消息、工具和终态边界刷新。保留旧事件格式，不改写旧历史。
- 测量打开各阶段的读入量、耗时和峰值内存，以及新增日志写入量。该测量用于选择第二窗口的最小实现。

**验收要求**

用两个请求在指定等待点交错，分别覆盖超时后重试、App 重启重连和首次打开无已保存 ID；只产生一个有效会话初始化。覆盖失败后重试、旧 worker 退出，以及成功／失败／取消／中断和空批次终态。原始文本、工具顺序、草稿和附件保持正确。

验证“已接收但未执行”不会被去重静默吞掉，副作用结果不确定时不会自动重放。合并日志后的完整内容一致；关键写盘失败可见，并明确尚未提交的流式尾部在强杀时的损失边界。

使用现场规模材料给出修复前后比较。扫描四遍变一遍可以作为本窗口收益，但不能据此宣布千万级历史按需读取已完成。

**回滚要求**

保持旧权威文件格式，新增派生信息可以忽略或重建。停止相关写入后，验证旧版能读取新版产生的记录再降级；不得为回滚恢复旧备份而覆盖新消息。若某项修复无法保持兼容，先明确其数据影响，不把格式迁移默认为本窗口的一部分。

### 第二窗口 完成大历史按需读取

**改动范围**

实现上文的小摘要、明确订阅边界、有限最近窗口和归档定位。发送、状态查询和取消不等待旧展示历史读取。按需读取同时限制条数与字节量，慢读者通过游标继续，避免无界排队且不静默丢事件。

同时检查 App 的 Chats JSON 和展示加载：不能后端只读尾部，App 又全量解码相同历史。只调整达到最近内容可用、旧内容按需读取所必要的保存与读取粒度。用户读取旧内容需要一个可用入口，但不要求任意位置跳转、复杂无限滚动或整套展示格式重写。

协议仅增加明确需要的状态／边界或范围读取能力，复用现有身份；按仓库规则同步类型与分发。若通用 TaskRegistry 仍使归档在启动时全部常驻，单独测量并限定修改范围，保留构建、安装和环境任务的恢复算法，不能顺带重做通用任务系统。

**验收要求**

- 以现场样本、百万和千万事件为容量场景，保持当前状态、模型上下文、未处理尾部和最近窗口相当。索引就绪后，正常打开的读取量与额外内存不能随归档总事件数线性增长。
- 冷启动、重新打开及发送新消息不遍历全部归档；状态查询和取消不排在全历史重放之后。旧记录仍可按明确请求读到。
- 范围读取与实时事件交接无缺失、无重复，断连后能继续；超大单条记录和慢消费者不会突破读取与排队预算。
- 摘要过期、索引损坏、残缺尾部和重建中断不丢当前状态，不错误恢复审批，不破坏原始归档。
- 若改动触及共享任务读取，补充受影响的构建、安装及环境任务恢复测试；未触及的子系统不承担整套新增故障矩阵。

**回滚要求**

优先保留原日志，将摘要、索引和最近窗口作为可丢弃的派生数据。禁用新读取路径或重建派生数据，不能删除唯一的未发送内容。旧程序回退可能重新出现性能问题，但不得造成内容损失。

需要改变权威文件布局时，先说明为什么兼容附加信息或派生缓存不足，并按下文回退规则选择最小方案；不预设长期双格式写入与完整反向导出。

### 第三窗口 复测与处理剩余问题

**改动范围**

首先验收前两窗口的正确性和百万到千万历史读取。若仍有不达标项，优先完成这些问题；若核心目标已满足，本窗口可以只做回归、修复和收尾，不必须新增存储机制。

候选优化按测量选择，不能整组打包：草稿附件外置、附件缓存限额、减少 App 保存写放大、已结束任务有限缓存、模型安全边界保存或模型图片外置。每项须有具体复现或测量、较小替代方案的比较、独立收益及明确回退范围。没有依据的项保留为观察事项，不列入发布承诺。

**验收要求**

前两窗口的核心目标不能因“不做大重构”而免除。额外选择的优化必须证明解决了对应瓶颈，并只扩展其影响范围内的测试；未选择的机制不成为验收欠项。保留现有模型字段、工具关系和审批行为，kwwk revision 不变。

**回滚要求**

逐项定义回退，避免把多个数据变更绑定成一次不可拆分的迁移。没有格式变化时使用代码回退或丢弃派生缓存；确有格式变化时遵循下一节，不承诺任意旧版本均能直接读新数据。

## 回退与数据安全的成本边界

优先不改变权威格式，其次增加可忽略字段或可重建旁文件。已有归档保持原样，不批量转换所有会话，不让两套存储各自异步写入后再猜哪份正确。

确实需要新权威格式时，只对相关会话转换，预检空间、保留原数据、验证后切换，并明确失败时当前版本如何继续读取。切换后新增内容必须保留，不能用迁移前备份冒充无损回滚。

完整反向导出和长期双格式兼容不再是默认交付项。新格式启用前必须明确选择：保留可直接降级的兼容表示、提供范围有限的一次性导出，或只支持当前兼容版本内关闭新路径／修复，不支持直接安装旧二进制。若产品要求无损二进制降级，导出及旧版读取验证就是该变更的真实成本，不能省略或声称备份已覆盖。

## 暂不承诺的设计

- 面向大量客户端的并发框架、持久化实例代次和通用事务身份系统。
- 完整模型检查点事务、多文件提交体系及精确续跑工具。
- 两次预定权威格式切换、通用迁移引擎、长期双向格式转换。
- 全局附件去重、自动删除历史、附件垃圾回收及强制日志分段。
- 通用 TaskRegistry 重构或按 Codex 实现复制的存储方案。

kwwk 已有消息初始化、状态读取和事件订阅接口，可供局部恢复改进使用，不要求引入其 SessionRecorder。其 ImageContent 仍要求 Base64 字符串：即使未来做图片持久化外置，也要在向 kwwk 提供上下文时还原，不能承诺内部惰性加载或请求流式编码。该限制进一步降低了本次提前改造模型图片存储的必要性。

## 按风险验证与发布

并发验证以两个请求的确定性交错为主，不设任意高并发数量门槛。容量验证保留百万与千万归档；它验证按需读取能力，不表示要同时运行大量模型或 worker。

在代表性真机记录数据规模、冷暖状态、索引是否存在、读取量、峰值内存、耗时和写入量。首次重建与日常打开分别统计，真实供应商网络耗时另列。先建立可复现基线，只对关键瓶颈作必要重复，不固定所有场景各跑 30 次，也不预先设没有基线支持的 1 秒／2 秒 P95 门槛。归档增长时不全读的约束必须满足，不能只用“这次读得够快”替代。

遵守 AGENTS.md 的 `make harness`、`make check` 和设备验证要求，按实际影响选择回归：纯持久化变化不把每种布局与每个故障点做笛卡尔积；触及包装路径、最低系统、UI 或共享任务时才扩展对应覆盖。协议和 worker 变化使用完整匹配包验证。

每个窗口发布前审查代码与数据差异、kwwk pin 和回退结果，保留安装包及 dSYM，按现有 CI 和发布规则交付。现场材料脱敏或合成为测试材料，不提交原聊天、附件、凭据、设备标识和本机路径。

每版之后依据实测重排剩余范围。消息丢失、重复副作用、终态倒退、权限变化或数据损坏须停止扩大使用并修复；三个窗口用完不等于自动完成，也不应为填满窗口增加重构。
